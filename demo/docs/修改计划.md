## 1. 问题①：文献解析后实验步骤出现重复

### 1.1 现象

用户上传文献并解析后，在「复现方案」页的"实验步骤"列表中出现多条内容高度相似的步骤（如同一操作被拆成多步、摘要与正文重复描述同一操作各生成一条）。

### 1.2 根因分析

- 步骤由 LLM 抽取：`extractDocument`（[pipeline.ts](file:///f:/chemistry/AIChemistry/demo/src/main/ai-server/experiment/pipeline.ts#L214-L255)）直接采用 `callJson<DocumentExtraction>` 返回的 `steps` 数组，**未做任何去重**。
- `EXTRACT_SYSTEM` 提示词（[pipeline.ts](file:///f:/chemistry/AIChemistry/demo/src/main/ai-server/experiment/pipeline.ts#L151-L172)）仅约束了步骤 JSON 结构，**未约束"步骤必须互斥、不得重复描述同一操作"**。
- 文献本身存在重复叙述（如摘要与实验部分的相同操作、英文摘要与中文译文的重复段落），LLM 易将其各自抽取为独立步骤。
- 落库路径 `parseDocumentsIntoProject`（[tools.ts](file:///f:/chemistry/AIChemistry/demo/src/main/ai-server/experiment/tools.ts#L530-L665)）是"先清空再写入"，逻辑上不会造成重复插入，故重复**来自抽取结果本身**。

### 1.3 修改方案

1. **提示词约束**（首选）：在 `EXTRACT_SYSTEM` 中新增硬性要求：
   - "步骤必须互斥：同一物理操作（含其目的与条件）只能出现一次，不得因摘要/正文重复描述而拆分或复述"；
   - "合并相似步骤：若两步标题或描述在语义上等价（如'加铜粉'与'一次性加入铜粉'），只保留信息最全的一条"。
2. **抽取结果去重**（兜底，`extractDocument` 返回前）：
   - 对 `steps` 按 `title + description` 归一化（去空白/标点/小写）后做相似度去重；
   - 相似度判断：归一化文本完全相同，或编辑距离 / 包含关系（如某条描述是另一条的近似复述）→ 保留 `step_no` 更小或描述更长的一条；
   - 去重后**重排 `step_no`**（保证 1..N 连续）。
3. **落库幂等**（双保险，`parseDocumentsIntoProject` 写入前）：对 `extraction.steps` 再做一次相同去重，防止未来其它入口（如 `create_project_from_documents`）绕过。

### 1.4 涉及文件

- `src/main/ai-server/experiment/pipeline.ts`：`EXTRACT_SYSTEM` 提示词 + `extractDocument` 去重函数
- `src/main/ai-server/experiment/tools.ts`：`parseDocumentsIntoProject`（落库前去重）
- `src/main/ai-server/experiment/prompt.ts`（如有需要，同步补充方案修改时的步骤去重约束）

### 1.5 验证方式

- 上传含重复描述（摘要 + 正文同一操作）的 PDF，解析后步骤数正确、无语义重复；
- 连续两次解析同一文献，步骤数量与内容一致（覆盖式无累积）。

## 2. 问题②：保存实验事件（带附件）报 `An object could not be cloned`

### 2.1 现象

在「阶段与记录」页保存**实验事件**并选择图片/视频附件后，控制台报错：

```
PhasePanel.vue:559 [Component] PhasePanel 保存事件失败: Error: An object could not be cloned.
    at submitEvent (PhasePanel.vue:545:29)
```

### 2.2 根因分析

- `eventForm.mediaPaths` 是 Vue **reactive 数组**（`reactive({ mediaPaths: [] })` 的代理对象）。
- 调用 `api.db.experiment.addEvent({ ... media_paths: eventForm.mediaPaths })` 时，该 **Proxy 被整体传入 `ipcRenderer.invoke`**，Electron 主进程与渲染进程之间使用**结构化克隆（structured clone）**，无法克隆 Vue Proxy → 抛 `An object could not be cloned`。
- 同类隐患：记录表单的 `form.attachments`（reactive 数组）在 `submitRecord` 中同样直接传入 `api.ai.saveRecord`，**带附件保存记录时也会触发同一错误**（当前仅事件被实测到）。

### 2.3 修改方案

1. **渲染进程修复**（首选）：
   - 事件保存：`media_paths: [...eventForm.mediaPaths]`（展开为普通数组）；
   - 记录保存：`attachments: form.attachments.length ? [...form.attachments] : undefined`；
   - 统一封装 `toPlain(value)`（`JSON.parse(JSON.stringify(value))` 或递归拷贝）供所有 IPC 出参使用，避免遗漏。
2. **主进程防御**（双保险）：`ExperimentDao.addEvent` / `addRecord` 参数中 `media_paths` / `attachments` 传入前统一做 `Array.isArray(x) ? x : []` 并 `JSON.stringify` 处理，即使渲染进程传入异常类型也不抛错。
3. **检索同型调用**：排查 `BranchPanel / ReferenceProjectsPanel / ChartDataRecorder` 等所有通过 `window.api` 传数组/对象的调用点，凡传 reactive 代理的一律先转普通值。

### 2.4 涉及文件

- `src/renderer/src/components/repro/PhasePanel.vue`：`submitEvent`、`submitRecord`（`media_paths` / `attachments` 展开拷贝）
- `src/main/database/dao/experiment.dao.ts`：`addEvent` / `addRecord` 数组参数防御
- 全局排查其余 IPC 调用点

### 2.5 验证方式

- 事件 + 图片附件保存成功、列表正常展示缩略图；
- 记录 + 图片/视频附件保存成功；
- 无附件场景回归不回归。

## 3. 问题③：步骤详情窗口（标签页模式）+ 数据归属到具体步骤

### 3.1 需求

在**步骤执行卡片**中的每一个步骤下，都应具备以下四类录入/展示能力：

- 阶段实验变量（该步骤的变量设定与本次实际取值）
- 实验事件（记录该步骤中影响后续实验的事件，可附图片/视频）
- 新增记录 / 现象（含附件、统计图录数）
- 自定义数据

**交互（用户建议，v2）**：

- 点击步骤执行卡片中的某个步骤后，**新建/激活一个"步骤详情窗口"**；
- 之后再点击其它步骤，**全部在该窗口内渲染**（复用同一个窗口，不重复开窗）；
- 窗口顶部为**步骤标签栏**：每个打开过的步骤一个标签，点击标签即可切换步骤；
- **同一窗口内步骤标签不允许重复**（已打开的步骤再次点击只激活已有标签，不新增标签）。

### 3.2 现状与差距

- 当前四类数据均挂在**阶段（phase_id）**或**项目**层级：变量按 `phase_id`、事件按 `phase_id`、记录按 `phase_id`、自定义数据按 `record_id`，**步骤无独立数据归属**。
- 前端 [PhasePanel.vue](file:///f:/chemistry/AIChemistry/demo/src/renderer/src/components/repro/PhasePanel.vue) 中这些卡片是"全局/阶段级"区块，不随步骤展开/收起。
- 步骤与阶段目前通过 `step_no` 松散关联（`createBranch` 中按阶段数均分步骤），无严格外键。

### 3.3 修改方案

#### 3.3.1 数据模型（新增 `step_id` 列，均可空，空 = 阶段级/项目级）

| 表 | 新增列 | 说明 |
| --- | --- | --- |
| `experiment_records` | `step_id INTEGER` | 记录归属步骤（空 = 阶段级） |
| `experiment_events` | `step_id INTEGER` | 事件归属步骤（空 = 阶段/项目级） |
| `experiment_phase_variables` | `step_id INTEGER` | 变量归属步骤（空 = 阶段级） |
| `experiment_custom_data` | `step_id INTEGER` | 自定义数据归属步骤（保留 `record_id`） |
| `prediction_experiments` | `step_id INTEGER` | 预测实验归属步骤（问题⑤联动，空 = 分支级） |

- 迁移：复用现有 `ensureColumn(table, column, ddl)` 机制逐列补列（旧库自动升级）。
- 外键：`step_id REFERENCES reproduction_steps(id) ON DELETE CASCADE`（注意 `reproduction_steps` 删除时级联清掉该步骤的数据）。
- `ProjectDao.delete` 级联删除清单无需改动（均随 `project_id` 清理；步骤删除级联由外键负责）。

#### 3.3.2 DAO / IPC

- `ExperimentDao.addRecord / addEvent / upsertPhaseVariable / addCustomData` 与 `PredictionDao.create` 增加 `step_id` 字段透传；
- 查询方法增加 `step_id` 过滤参数（`records(projectId, branchId, stepId?)` 等）；
- 新增 IPC：`db:step-record-list`、`db:step-event-list`、`db:step-variable-list`、`db:step-custom-list`（或统一在 `db:project-context` 中返回后前端过滤，优先后者，避免 IPC 膨胀）。
- `ProjectContext` 增加各表的 `step_id` 字段回传，前端一次拉取后本地过滤。

#### 3.3.3 前端交互（步骤详情窗口 + 标签页，v2）

- **步骤详情窗口**（新增组件 `StepDetailWindow.vue`，挂载在 PhasePanel 步骤执行卡片旁，固定区域展示）：
  - 步骤执行卡片中每个步骤增加"打开详情"入口；
  - 点击步骤 → 若窗口尚未打开过该步骤，则在窗口标签栏**新增一个步骤标签**并激活；若已打开过，**仅激活已有标签（不新增，保证标签唯一）**；
  - 之后点击其它步骤，均在该窗口内渲染，**不重复开窗**；
  - 标签栏：`步骤N · 标题` 标签 + 关闭按钮；点击标签切换步骤；可关闭标签（关闭后再次点击步骤可重新打开）；
  - 同一窗口**步骤标签去重**（以 `step_id` 为唯一键校验，不出现同名/同步骤重复标签）。
- **窗口内容**：当前激活步骤的四个子模块——阶段变量 / 实验事件 / 新增记录现象 / 自定义数据（含附件、统计图录数）；
- 各表单默认绑定当前激活步骤的 `step_id`；
- 记录/事件/变量/自定义数据的查询展示按 `step_id` 过滤（空值兼容展示阶段级/项目级数据，如"该步骤 + 阶段级"聚合视图）；
- 切换标签（步骤）时表单状态按步骤缓存（`Map<step_id, 表单状态>`），避免用户录入中途切换丢失；窗口布局与子模块可复用现有表单组件。

### 3.4 涉及文件

- `src/main/database/sqlite.ts`（建表/迁移）
- `src/main/database/dao/experiment.dao.ts`、`prediction.dao.ts`（step_id 透传 + 过滤）
- `src/main/database/index.ts`（IPC + context 回传）
- `src/main/ai-server/type.ts`（类型增加 `step_id`）
- `src/main/ai-server/experiment/tools.ts`（save_experiment_record / save_experiment_event / update_phase_variables 支持 step_id）
- `src/renderer/src/stores/repro.ts`（UI 类型 + 过滤）
- `src/renderer/src/components/repro/PhasePanel.vue`（步骤详情窗口入口 + 标签栏）
- `src/renderer/src/components/repro/StepDetailWindow.vue`（**新增**：步骤详情窗口 + 步骤标签页 + 四类子模块）

### 3.5 验证方式

- 点击步骤 A → 打开步骤详情窗口并出现标签；再点步骤 B → 窗口内新增 B 标签并切换；再点 A → **不新增标签，仅激活 A**；
- 关闭标签后再点该步骤 → 重新打开；
- 在步骤 A 标签录入事件/记录/变量/自定义数据 → 切到步骤 B → 不显示 A 的数据，切回 A 数据仍在（状态缓存）；
- 删除步骤 A → A 的变量/事件/记录/自定义数据随外键级联删除；
- 无步骤数据（阶段级）的场景兼容显示。

## 4. 问题④：步骤执行卡片的增 / 删 / 改

### 4.1 需求

用户在「步骤执行」卡片中可以直接：

- **新增步骤**（插入到指定位置，重排 `step_no`，重建依赖）
- **删除步骤**（其下归属数据随外键级联清理，后继依赖自动重算）
- **修改步骤**（标题 / 描述 / 条件 / 时长 / 备注 / 依赖关系）

### 4.2 现状

- DAO：`ReproductionDao` 有 `addStep / clearSteps / setStepDependencies / updateStepStatus / recomputeReady`，**缺少 `updateStep` 与 `deleteStep`**；
- IPC：仅 `db:step-update-status` / `db:step-ready-list` / `db:step-recompute`，**无增删改通道**；
- 前端步骤卡片仅"开始/完成/跳过"按钮，**无编辑表单与新增/删除按钮**。

### 4.3 修改方案

#### 4.3.1 DAO（`reproduction.dao.ts`）

- `updateStep(id, patch)`：支持 `step_no / title / description / conditions / duration / notes / depends_on`；
- `deleteStep(id)`：
  - 先查出该步骤的 `project_id / branch_id`；
  - 删除步骤（外键级联清理其下变量/事件/记录/自定义数据/预测）；
  - 该分支内其余步骤的 `depends_on` 引用该 id 的全部剔除；
  - 重排 `step_no`（1..N 连续）并调用 `recomputeReady` 解锁。
- `insertStep(projectId, { step_no, ... })`：新增步骤后插入指定位置，重排 `step_no`，默认 `status='pending'`，`depends_on` 由用户/前端指定（默认空）。

#### 4.3.2 IPC / preload

- 新增：`db:step-update`、`db:step-add`、`db:step-delete`；
- preload `api.db.experiment` 增加 `updateStep / addStep / deleteStep`；`index.d.ts` 同步。

#### 4.3.3 前端（PhasePanel 步骤卡片）

- 每张步骤卡片右上角：**编辑**（inline 表单：标题/描述/条件/时长/备注/依赖多选）与**删除**（确认后调用）；
- 卡片列表底部/卡片间：**＋新增步骤**（选择插入位置）；
- 删除/新增/修改后 `refreshContext()` + 事件广播刷新。

### 4.4 涉及文件

- `src/main/database/dao/reproduction.dao.ts`
- `src/main/database/index.ts`
- `src/preload/index.ts`、`index.d.ts`
- `src/renderer/src/components/repro/PhasePanel.vue`

### 4.5 验证方式

- 修改步骤标题/条件后保存生效；删除步骤后其数据级联清空、`step_no` 连续；新增步骤后按位置插入、依赖正确。

## 5. 问题⑤：预测实验并入「阶段与记录」（删除独立 Tab）

### 5.1 需求

- **删除"预测实验"独立 Tab**（`ReproductionLab.vue` 的 `prediction` 页签移除）；
- 预测实验作为**「阶段与记录」的一个模块**：
  - **每个执行步骤**下提供"AI 预测实验"入口（预测当前步骤改变变量后的结果，关联 `step_id`）；
  - **每个并行实验（分支）**下提供预测入口（关联 `branch_id`）；
  - 综合对比分析（`comprehensive_analysis`）入口一并迁入阶段与记录模块。

### 5.2 现状

- `PredictionPanel.vue` 是独立 Tab 组件，含"运行 AI 预测实验"与"综合对比分析"；
- 预测数据 `prediction_experiments` 仅按 `branch_id` 关联（空 = 主线），无 `step_id`；
- `run_prediction_experiment` 工具已支持 `branch_id`（见 [tools.ts](file:///f:/chemistry/AIChemistry/demo/src/main/ai-server/experiment/tools.ts#L1537-L1555) 附近的 `runPredictionExperimentTool`）。

### 5.3 修改方案

#### 5.3.1 数据模型

- `prediction_experiments` 增加 `step_id INTEGER`（可空，空 = 分支级/主线级），随步骤删除级联清理。

#### 5.3.2 工具 / 后端

- `run_prediction_experiment` 的 schema 增加可选 `step_id`（描述"对哪个步骤做预测"）；
- `list_experiment_variables` 支持按 `step_id` 过滤（列出该步骤变量 + 分支变量）；
- `comprehensive_analysis` 汇总时纳入步骤维度数据。

#### 5.3.3 前端

- `ReproductionLab.vue`：移除 `prediction` Tab 与 `PredictionPanel` 挂载；
- `PredictionPanel.vue` 改造为**可嵌入模块** `PredictionModule.vue`（props：`projectId / branchId / stepId?`）：
  - 在 PhasePanel 的每个**步骤卡片展开区**嵌入（绑定该步骤 `step_id`）；
  - 在**分支面板（BranchPanel 或分支详情）**嵌入（绑定 `branch_id`）；
  - "综合对比分析"按钮置于阶段与记录页顶部或分支面板（跨分支对比）。
- 预测历史列表按 `branch_id + step_id` 过滤展示，标注"步骤 X · 分支 Y"。

### 5.4 涉及文件

- `src/renderer/src/views/ReproductionLab.vue`（删 Tab）
- `src/renderer/src/components/repro/PredictionPanel.vue` → 新增 `PredictionModule.vue`
- `src/renderer/src/components/repro/PhasePanel.vue`、`BranchPanel.vue`（嵌入模块）
- `src/main/ai-server/experiment/tools.ts`（run_prediction_experiment / list_experiment_variables 支持 step_id）

### 5.5 验证方式

## 6. 问题⑥：步骤级并行实验（步骤内变量变体，可新建/删除/修改）

### 6.1 需求（用户建议，v2）

- 在**具体步骤**中可**修改该步骤的实验变量**，据此**生成不同的并行实验**（步骤级变体）；
- 用户可自定义在步骤中**新建 / 删除 / 修改**并行实验；
- 每个步骤级并行实验拥有独立的数据空间（变量取值、记录/现象、事件、自定义数据、预测），互不干扰；
- 与既有"分叉点阶段"树分叉（`project_branches`，fork_phase_id）**并存**：步骤级变体归属在某个分支（branch）内，变体间共享该步骤的步骤信息，仅变量设定与后续数据独立。

### 6.2 现状与差距

- 当前并行实验仅支持**阶段级分叉**（`project_branches`，`fork_phase_id` 复制分叉点后所有阶段），**无步骤级并行实验**；
- `experiment_phase_variables` 的 `current_value` 可被修改，但修改会直接覆盖该步骤原值，**无法保存多套取值并存比较**；
- 无"步骤内变体"的数据模型与 UI。

### 6.3 修改方案

#### 6.3.1 数据模型（新增 `step_experiments` 表）

```
CREATE TABLE IF NOT EXISTS step_experiments (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  project_id INTEGER NOT NULL,
  step_id INTEGER NOT NULL,            -- 所属步骤（reproduction_steps.id）
  branch_id INTEGER,                   -- 所属分叉（空 = 主线），与步骤 branch_id 一致
  parent_experiment_id INTEGER,        -- 从某变体再派生（可空，形成变体树）
  name TEXT NOT NULL,                  -- 变体名，如"变体A-温度80°C"
  description TEXT DEFAULT '',
  variable_overrides TEXT DEFAULT '{}',-- 相对步骤默认变量的覆盖 JSON（{key: value}）
  status TEXT DEFAULT 'pending',       -- pending/indexed（完成变体后延迟入库）
  created_at TEXT
)
```

- **数据归属**：`experiment_records / experiment_events / experiment_custom_data / experiment_phase_variables / prediction_experiments` 在问题③新增 `step_id` 的基础上，**再增加 `step_experiment_id INTEGER`（可空，空 = 步骤默认执行）**，使每个变体拥有独立数据空间；
- **删除级联**：删除变体 → 事务内清理该变体下全部数据；删除步骤 → 级联清理步骤及其所有变体数据（`deleteStep` 手动处理）。

#### 6.3.2 DAO / IPC

- 新增 `StepExperimentDao`（或并入 `ExperimentDao`）：
  - `list(projectId, stepId, branchId)` / `create({project_id, step_id, branch_id, parent_experiment_id?, name, description, variable_overrides})` / `update(id, patch)` / `delete(id)`（含级联清数据）；
  - 步骤默认执行体以 `step_experiment_id = NULL` 表示，与变体并列展示；
- 新增 IPC：`db:step-experiment-list` / `-create` / `-update` / `-delete`；preload 与 `index.d.ts` 同步；
- `ProjectContext` 增加 `stepExperiments` 数组回传，前端本地过滤。

#### 6.3.3 前端（StepDetailWindow 内"并行实验"子模块）

- 步骤详情窗口新增**并行实验子模块**（在四类子模块之上）：
  - **默认执行**（`step_experiment_id=null`）+ 各变体卡片：名称、变量覆盖摘要（如"温度 80°C；时间 2h"）、状态、创建时间；
  - **新建并行实验**：弹窗内列出该步骤全部实验变量，用户修改取值后生成变体（`variable_overrides` 记录与默认值的差异），支持"从某变体再派生"；
  - **修改**：编辑变体名、描述、变量覆盖取值（保存后该变体数据保留）；
  - **删除**：确认后删除变体及其全部数据；
  - 点击某变体 → 下方四类子模块（变量/事件/记录现象/自定义数据）切换为该变体的数据空间（`step_experiment_id` 过滤）；
- 步骤执行卡片 / 分支面板的"预测实验"入口自动继承当前激活变体（问题⑤联动 `step_experiment_id`）。

### 6.4 涉及文件

- `src/main/database/sqlite.ts`（建表 + `step_experiment_id` 迁移）
- `src/main/database/dao/experiment.dao.ts`（StepExperiment CRUD + 记录/事件/变量/自定义数据 `step_experiment_id` 透传与过滤）
- `src/main/database/dao/reproduction.dao.ts`（`deleteStep` 级联清理变体及其数据）
- `src/main/database/index.ts`（IPC + context 回传）
- `src/main/ai-server/type.ts`（`StepExperiment` 类型 + 各实体增加 `step_experiment_id`）

### 6.5 验证方式

## 7. 问题⑦：文献上传后紧接着进行图表解析

### 7.1 需求（用户建议，v3）

- **图表解析应在用户上传完文献之后紧接着进行**（MinerU 解析完成 → 立即进入图表解析），无需用户额外操作或后续手动触发。

### 7.2 现状与差距

- 当前 `file:import`（[files/index.ts](file:///f:/chemistry/AIChemistry/demo/src/main/files/index.ts#L34-L85)）中：
  - 本地降级路径（`parser !== 'mineru'`）会调用 `parseDocumentFigures(id, images, tables)` 解析图表；
  - **MinerU 路径下 `images = []` 被置空**，未走图表解析，因此 MinerU 解析的文献实际上**没有图表入库**；
- `parseDocumentsIntoProject` 解析方案后也未触发图表解析；
- 图表面板（`FigurePanel`）只能展示已入库的 `document_figures`，MinerU 文献下为空。

### 7.3 修改方案

1. **MinerU 解析返回结构化图/表数据**：`parsePdfWithMineru`（[mineru.ts](file:///f:/chemistry/AIChemistry/demo/src/main/files/mineru.ts)）在重建 `text / tables` 时，同时收集 `content_list.json` 中的**图片块（figures）与表格块（tables）**，随 `DocumentImportResult` 一并返回（`figures` 数组）。
2. **导入即解析**：`file:import` 在 MinerU 分支不再置空 images，而是将 MinerU 返回的图/表数据**直接送入 `parseDocumentFigures`**（图片走 DeepSeek-VL2 / OCR 兜底，表格结构化入库），生成 `document_figures` 记录。
3. **方案解析后二次补全**：`parseDocumentsIntoProject` 完成后，若该项目仍存在 `document_figures` 为空（或图表数据未提取）的文献，自动补跑一次图表解析（幂等，不重复入库）。
4. **进度反馈**：图表解析耗时较长时，通过现有事件通道（`experiment:state-changed`）广播"图表解析完成"，前端刷新图表面板与步骤图表。

### 7.4 涉及文件

- `src/main/files/mineru.ts`（返回 figures 结构化数据）
- `src/main/files/index.ts`（`file:import` 两分支均执行图表解析）
- `src/main/files/figures.ts`（支持 MinerU 图片块/表格块直接结构化）
- `src/main/ai-server/experiment/tools.ts`（`parseDocumentsIntoProject` 补跑图表解析）

### 7.5 验证方式

- 上传 MinerU 文献 → 导入完成后 `document_figures` 已有数据，图表面板可查看；
- 解析方案后再次确认图表解析自动完成（无手动入口也可）。
